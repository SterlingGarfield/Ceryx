# Ceryx v0.3 Master Execution Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Ceryx v0.3 as a dual-control product: iPad App, Desktop App, and Windows Agent working through one secure local protocol.

**Architecture:** The product is split into platform shells, shared frontend packages, and a Windows Agent. The control apps never perform system operations directly; all system-level actions go through Agent APIs, permissions, session lock, and audit logs.

**Tech Stack:** pnpm workspace, React, TypeScript, Vite, Tailwind CSS, Capacitor, Tauri 2, .NET 10 LTS, ASP.NET Core Kestrel, WinUI 3 tray/settings, SQLite, Windows.Graphics.Capture, Win32 SendInput.

## Global Non-Negotiables

- Desktop App cannot bypass Agent for system commands, file opening, capture, input, screenshot, recording, or logs.
- Remote clients cannot close or restart Agent; only local Desktop can request local Agent management actions.
- Default capture target is Codex window only, never the whole desktop.
- Only one active controller can inject input into one Codex window at a time.
- Every control action must pass token validation, permission validation, session validation, and audit logging.
- Large diff and logs are paginated or loaded per file; no full unbounded payloads.
- W1-W3 must finish before capture/input work begins.
