# Ceryx v0.3 W4 Remote Control Transport Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Agent-side Codex window discovery, capture lifecycle, input bridge, prompt send, image send, screenshot, and recording service boundaries behind permissions and session lock.

**Architecture:** Network routes call service interfaces only. `Ceryx.Agent.Codex` owns window location, focus, input, clipboard, and image bridge. `Ceryx.Agent.Capture` owns capture lifecycle and frame transport. `Ceryx.Agent.Media` owns screenshots, recordings, asset storage, and cleanup.

**Tech Stack:** .NET 10, Win32 EnumWindows, Windows.Graphics.Capture, SendInput, Windows Clipboard APIs, WebSocket, WebRTC signaling stub, SQLite audit log.

---

## Success Criteria

- Agent reports Codex window states: `not_found`, `found`, `focused`, `minimized`, `multiple_candidates`, `permission_issue`.
- Capture can start/stop for the bound Codex window without exposing full desktop capture.
- Input commands are accepted only for active session with `control_input`.
- Prompt send uses clipboard paste plus optional submit.
- Image upload saves assets and attempts image paste strategy.
- Screenshot and recording APIs are permission-gated and audited.

## Task 1: Codex Window Locator

- [ ] Implement process-name and window-title matching.
- [ ] Add manual select endpoint `POST /api/v1/codex/select-window`.
- [ ] Add `GET /api/v1/codex/window`, `POST /api/v1/codex/focus`, `POST /api/v1/codex/refresh`.
- [ ] Return `multiple_candidates` instead of guessing when more than one Codex-like window exists.

Run:

```powershell
dotnet test agent/windows/Ceryx.Agent.Windows.sln --filter WindowLocator
```

Expected: matching priority and multiple-candidate behavior pass.

## Task 2: Session Lock

- [ ] Implement one active input controller per Codex window.
- [ ] Allow standby viewers without input rights.
- [ ] Add timeout/heartbeat release for stale active session.
- [ ] Emit audit events when active control changes.

Run:

```powershell
dotnet test agent/windows/Ceryx.Agent.Windows.sln --filter SessionLock
```

Expected: simultaneous input sessions are rejected.

## Task 3: Input and Prompt Bridge

- [ ] Implement input DTOs for mouse, keyboard, hotkey, scroll, and text paste.
- [ ] Map DTOs to SendInput commands in a testable mapper.
- [ ] Before input, validate token, permission, session lock, and bound Codex window.
- [ ] Implement `POST /api/v1/prompt/send` using clipboard paste plus optional Enter.
- [ ] Record audit log for accepted and rejected input.

Run:

```powershell
dotnet test agent/windows/Ceryx.Agent.Windows.sln --filter InputMapping
dotnet test agent/windows/Ceryx.Agent.Windows.sln --filter PromptSend
```

Expected: prompt send rejects missing permission and logs successful sends.

## Task 4: Capture Transport

- [ ] Implement capture lifecycle service with modes: Low Latency, Balanced, High Quality, Power Save.
- [ ] Start capture only for bound Codex window.
- [ ] Pause capture if Codex is minimized.
- [ ] Add WebSocket status events for `capture.started`, `capture.stopped`, and `capture.resized`.
- [ ] Add WebRTC signaling endpoints as structured stubs if full WebRTC is not stable yet.

Run:

```powershell
dotnet test agent/windows/Ceryx.Agent.Windows.sln --filter CapturePolicy
```

Expected: full-desktop capture is rejected by default.

## Task 5: Image, Screenshot, Recording

- [ ] Implement `POST /api/v1/assets/upload-image` with 20MB limit and extension validation.
- [ ] Save uploads under `%LOCALAPPDATA%/Ceryx/Uploads`.
- [ ] Implement `POST /api/v1/media/screenshot` for Codex window only.
- [ ] Implement recording start/stop state with max 30 minutes and disk-space precheck.
- [ ] Save recordings under `%USERPROFILE%/Videos/Ceryx`.

Run:

```powershell
dotnet test agent/windows/Ceryx.Agent.Windows.sln --filter MediaPolicy
```

Expected: large uploads, low disk, and duplicate recording requests are rejected.
