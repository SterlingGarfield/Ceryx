# Ceryx v0.3 W3 Pairing and Discovery Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement local-network discovery, pairing, trusted devices, token validation, reconnect behavior, and permission-aware request guards.

**Architecture:** Discovery publishes Agent metadata through mDNS. Pairing creates trusted devices only after Windows-side confirmation and code verification. Token validation and permission checks become middleware used by all control APIs from W4 onward.

**Tech Stack:** .NET 10, ASP.NET Core filters/middleware, SQLite repositories, DNS-SD/mDNS library, cryptographic token hashing, Vitest client SDK tests.

---

## Success Criteria

- Agent publishes `_ceryx-agent._tcp.local` metadata.
- Pairing request, confirm, expiry, lockout, and trusted-device persistence work.
- Authenticated requests reject missing, invalid, or deleted tokens.
- Client SDK supports pairing and reconnect state.
- iPad/Desktop connection screens can consume discovery and pairing APIs.

- [ ] Pairing code is six digits and expires after 120 seconds.
- [ ] Allow only one pending pairing request at a time.
- [ ] Lock pairing for 5 minutes after 5 failed attempts.
- [ ] Add audit logs for request, confirmation, failure, success, expiry.
